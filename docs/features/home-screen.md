# Feature notes: The web client on a phone's home screen

Part of the project description (entry point: root `AGENTS.md`, section 0). Dated entries: what was built, the user's wishes and decisions, consequences, and what was and was not checked.

Code: `apps/web/index.html` (manifest link, Apple tags), `apps/web/src/branding.ts` (`applyHomeScreenName`), `apps/web/public/app-icons/` (generated by `tools/web-app-icons.mjs`), `apps/server/src/webManifest.ts` and the route `GET /api/manifest.webmanifest` in `apps/server/src/index.ts`.

**Squorli logo and "Squorli - <server name>" on the home screen (19 September 2026, user's wish):** "beim Speichern als Homebildschirm App soll sowohl bei iPhone als auch bei anderen Mobilgeräten das Squorli Logo verwendet werden" and "als Name soll dann Squorli - Servername angeboten werden". Until then the client had no manifest and no Apple tags; iOS took a screenshot of the page as the icon.
- *Icons:* `tools/web-app-icons.mjs` renders `docs/brand/squorli-icon.svg` on the brand's ground `#0C1424` with headless Chrome (like `tools/desktop-icon.mjs`): `apple-touch-icon.png` 180 px, full square without transparency (iOS rounds it itself and turns transparency black); `icon-192.png` and `icon-512.png` with the rounded tile of the desktop app's icon (purpose `any`); `icon-maskable-512.png` full square with the mark inside the safe inner 80 % (purpose `maskable`, Android cuts its own shape). Committed, regenerate only after a brand change. It is always the Squorli mark, never the server's own icon from the admin panel (user's wish).
- *Name:* it contains the server's name, so the manifest cannot be a static file. The app server answers `GET /api/manifest.webmanifest` from its settings (`webManifest.ts`, tested; `no-cache`; under `/api` so that Vite's dev proxy reaches it too). Both `name` and `short_name` carry "Squorli - <name>", plain "Squorli" without one. iOS reads the name from `<meta name="apple-mobile-web-app-title">` instead, which `branding.ts` completes once the name is known. Always the HOME server (the one that serves the page and that the icon opens), not the server displayed at the moment. The phone only OFFERS the name, the user can change it; a long name is cut off under the icon by the phone.
- *Opens as an app:* `display: standalone`, `start_url` and `scope` `/`, ground and theme colour `#0C1424`. No `apple-mobile-web-app-status-bar-style` (translucent would put the page under the status bar, and the page has no `viewport-fit=cover`), no service worker, no offline mode.
- *Caching:* the server lets browsers cache every static file that is no page for a year, the icons included. Their addresses carry `?v=1`; after regenerating them raise it in `index.html` and `APP_ICON_VERSION` in `webManifest.ts`.
- *Storage:* an installed web app has storage of its own on iOS: whoever signs in there without the directory account is another identity than in Safari.
- *The desktop app* loads the same `index.html` from `app://squorli`; the manifest link finds nothing there and nothing uses it.
- *Checked:* typecheck, tests (server 55, 2 new in `webManifest.test.ts`), build. Against the running dev server: the route answers `application/manifest+json`, `no-cache`, name "Squorli - Test Server", through :3000 and through Vite on :5173; the icons are served; the four PNGs were looked at (sizes 180/192/512/512, mark centred, maskable inside the safe zone).
- *NOT checked:* adding to the home screen on a real iPhone or Android phone (icon, offered name), Chrome's install prompt, the smoke test (no check for the new route was added).

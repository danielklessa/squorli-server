# Feature notes: Admin panel and general UI (roles, channels, context menus, UI refresh)

Part of the project description (entry point: root `AGENTS.md`, section 0). Dated entries: what was built, the user's wishes and decisions, consequences, and what was and was not checked. Standing rules live in the `AGENTS.md` of the area. Whoever changes the feature adds or updates its entry here in the same step.

Code: `apps/web/src/AdminPanel.tsx`, `roleOrder.ts`, `ChannelsTab.tsx`, `channelOrder.ts`, `ContextMenu.tsx`, `menuPosition.ts`, `Avatar.tsx`, `styles.css`.

**Compact role rows (17 September 2026):** Role drag handle, name and both arrow buttons share one grid row. Names truncate with an ellipsis and expose the full name in a tooltip; the default-role label stays inline. This keeps the left role list compact without changing ordering behavior.

**Role ordering (17 September 2026):** The Roles tab in `AdminPanel.tsx` replaces the numeric position field with drag handles, insertion markers and up/down controls in the left-hand role list. Focused handles also accept arrow keys. Ordering saves immediately through the existing role API, separately from unsaved name/color/permission edits. `App.tsx` supplies the active user ID so own/higher roles and the default role cannot be dragged; owners can reorder all non-default roles. `roleOrder.ts` preserves rank slots and repairs ties without crossing the actor's rank boundary. Four tests cover directions, fixed roles, ties, owner access and no-op drops. Typecheck, all 97 tests and production build passed. Browser visual/drag acceptance remains pending (no connected browser). No backend, protocol or brand changes.

**Channel management (17 September 2026):** `apps/web/src/ChannelsTab.tsx` separates channel names/actions from category, topic and audio controls in responsive editors. Categories and channels can be reordered with native drag handles and before/after insertion markers; grouped up/down buttons remain available for touch and keyboard use, and focused handles accept arrow keys. Reordering uses the existing update endpoints, serializes writes and disables further reorder actions while saving. `channelOrder.ts` normalizes positions, including duplicate legacy values; four unit tests cover insertion in both directions, boundaries and stale IDs. German/English labels and save status are included. Typecheck, all 93 tests and production build passed; visual and native drag interaction verification remains pending because no browser was connected. Existing brand tokens are reused without brand-package or sibling-project changes.

**Member context menus (15 September 2026):** Member buttons open a floating body-portal menu on right-click or ordinary click (also keyboard/touch). `ContextMenu.tsx` supplies viewport positioning, outside dismissal, Escape/Tab handling and arrow-key navigation; role selection and voice-channel moves use hover/click/keyboard submenus that flip left near the viewport edge. Existing moderation permissions and confirmation dialogs are preserved. `menuPosition.test.ts` covers six placement cases. No server, protocol or brand-package change.

**Web UI refresh (15 September 2026):** The browser client uses the existing version 2 brand tokens for a framed conversation area, roomier navigation, member handles and a profile dock. `apps/web/src/Avatar.tsx` is the shared image/initials presentation component for channel messages, DMs, members, friends, voice participants and profile previews. It accepts an optional image URL and falls back on load errors; avatar upload, persistence and protocol fields are not implemented. At <=700 px, navigation is collapsible and the server rail is horizontal. The brand package and sibling projects are unchanged. Verification: typecheck, all 50 tests and production build passed; browser visual/interaction review remains pending because no browser was available.

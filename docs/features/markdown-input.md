# Feature notes: Markdown in messages and the message input

Part of the project description (entry point: root `AGENTS.md`, section 0). Dated entries: what was built, the user's wishes and decisions, consequences, and what was and was not checked. Standing rules live in the `AGENTS.md` of the area. Whoever changes the feature adds or updates its entry here in the same step.

Code: `apps/web/src/markdown.ts`, `MessageText.tsx`, `AutoGrowTextarea.tsx`, `autoGrow.ts`, the composers of `ChatView.tsx` and `DmView.tsx`. Emoji conversion: `docs/features/emoji.md`.

**More Markdown (17 September 2026, user's wish):** task lists (`- [ ]`, `- [x]`, also numbered and nested; rendered as a disabled checkbox that shows the written state, `ListItem.checked`), highlight `==text==` (`<mark>`, quiet amber), subscript `H~2~O` and superscript `x^2^` (single `~`/`^` on both sides and no white space inside, so `~5 min, ~10 min` and `2^10` stay text; `~~` stays strikethrough). `=` follows the intraword rule of `_` (`a==b` and `x == y` stay text); content consisting only of the delimiter (`=====`) is no markup.

**Focus stays in the message input (17 September 2026, user's wish):** after sending (Enter or the button) the composer of `ChatView` and `DmView` keeps/gets the focus, so the next message can be typed right away. Cause was `disabled` while sending, which drops the focus; the input is now `readOnly` during the request (still `disabled` without `SEND_MESSAGES`) and `submit()` focuses it in `finally`. `AutoGrowTextarea` takes `inputRef` for this and for the emoji picker.

**Growing message input (17 September 2026, user's wish):** the composer of the channel chat and of the direct messages, and the field for editing a message, grow with their content up to **one third of the chat area's height** (`.chat`) and only then scroll. `apps/web/src/AutoGrowTextarea.tsx` measures `scrollHeight` in a layout effect on every value change and follows size changes of the area with a `ResizeObserver` (script instead of CSS `field-sizing`, which Firefox lacks); the rule itself is the pure `grownHeight()` in `autoGrow.ts` (`INPUT_MAX_SHARE` = 1/3, never below `INPUT_MIN_LIMIT` = 64 px so a phone with the keyboard open keeps about two lines; tested). The fixed `max-height: 10rem` of `.composer-row textarea` is gone. `ChatView.tsx` and `DmView.tsx` observe the message list and keep the newest message in view while the input grows or shrinks (only if the user has not scrolled up). Typecheck, all tests and build green; not checked in a browser.

**Markdown in the text chat (17 September 2026, user's wish):** channel messages and direct messages are rendered as Markdown by the shared `apps/web/src/MessageText.tsx`; it replaces the two copies of `renderText` (links only) in `ChatView.tsx` and `DmView.tsx`. `apps/web/src/markdown.ts` is an own, pure parser (text -> tree; no library, following "no new dependencies": Claude's decision, not confirmed by the user); the component turns the tree into React elements, message text never becomes HTML (`dangerouslySetInnerHTML` stays taboo). Deliberately a chat subset, not full CommonMark: paragraphs where a single line break stays a line break, headings `#` to `###` (rendered as h3-h5, the page owns h1/h2), fenced code (also ```` ```one line``` ````; an unclosed fence stays text; no syntax highlighting, the language is only `data-lang`), quotes `> ` (space required, nesting capped at 6), bullet and numbered lists nested by indentation (start number kept; a number other than 1 does not interrupt a paragraph), rule, `code`, `**strong**`/`__strong__`, `*em*`/`_em_` (no `_` emphasis inside words), `~~del~~`, `[text](url)`, `<url>`, bare URLs (trailing sentence punctuation excluded), backslash escapes. **Link safety:** only `http`, `https` and `mailto` become links; a masked link whose label itself looks like a web address is refused and stays literal (phishing); every link shows its target as `title` and opens with `noreferrer noopener`. **Link previews (21 September 2026, `docs/features/link-previews.md`) keep this rule:** their pictures are copies on the chat server, and `readBareUrl` now lives in `packages/protocol/src/links.ts` so the server finds the same addresses the parser shows. **Images are never embedded** (`![alt](url)` becomes a link): a remote image would reveal the reader's IP address to a foreign host; uploaded attachments are unchanged. **Tables (GFM, user's wish):** a header row followed by a delimiter row (`---`, `:--`, `:-:`, `--:` = alignment) with the same number of cells; the delimiter row is what tells a table from a sentence containing `|`. Outer pipes are optional, `\|` is a pipe inside a cell, body rows run until a blank line or a line without `|` and are cut or filled to the header's width, at most 32 columns, cells take inline formatting; a table may interrupt a paragraph; rendered inside `.md-table`, which scrolls sideways instead of widening the chat. **Copy button on code blocks (user's wish):** every fenced block carries a button (top right, on hover or keyboard focus, always visible on touch) that copies exactly the block's content; Clipboard API with a fallback to the selection command for plain http, a check mark and a `role="status"` text confirm for two seconds (`chat.copyCode`, `chat.codeCopied`, `chat.codeCopyFailed`; icons `copy`, `check`). Inline code has no button. Not supported on purpose: raw HTML, indented code, setext headings, underline/spoilers. Storage, protocol and server are untouched: messages stay plain text, editing shows the raw Markdown, `PROTOCOL_VERSION` stays 4. The component is memoized because the chat views re-render on every composer keystroke. The "(bearbeitet)" mark sits in the last paragraph/heading, or in its own line after a code block/list/quote. Tests: `markdown.test.ts` (25, including tables and hostile input within a time bound) and `MessageText.test.tsx` (5, `renderToStaticMarkup`: no markup injection, link attributes, edited mark). Typecheck, all tests and build green; the look in a browser was not checked.

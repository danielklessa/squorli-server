# Feature notes: AFK detection and AFK channel

Part of the project description (entry point: root `AGENTS.md`, section 0). Dated entries: what was built, the user's wishes and decisions, consequences, and what was and was not checked. Standing rules live in the `AGENTS.md` of the area. Whoever changes the feature adds or updates its entry here in the same step.

**AFK detection, AFK channel, AFK in the friends list (17 September 2026, user's requirement):** a user counts as absent (AFK) after 10 minutes without activity (`AFK_AFTER_MS`, fixed for everyone). An admin names one voice channel the AFK channel; a member who is absent in a voice channel is moved there. In the AFK channel microphone and audio are always off and camera or screen share are impossible. The state goes to the directory too, so friends see it.

The user's decisions (asked on 17 September 2026):
- **What counts as activity:** input in a Squorli window (pointer, keys, wheel, touch; video pop-outs included), **speaking** (open speech gate of an unmuted microphone, so somebody who plays and talks is not moved), and **system-wide input through the Idle Detection API** where the browser has it (Chromium) and the user switched it on. The browser asks for that permission and only inside a click, so it is a switch in Einstellungen > Ansicht ("Abwesenheit"), stored per browser (`chat.idleDetection.v1`), not in the directory account: the permission belongs to the browser. While the detector reports the user active they are never idle; once it reports idle or a locked screen, the ten minutes without input or speech decide. Firefox and Safari work from the first two alone.
- **Coming back:** the user stays in the AFK channel; the dock says why they are there and offers "Zurück zu <Kanal>". Never automatically: a stray mouse move must not put a microphone back on air.
- **Exception from the move:** nobody is moved out of a channel whose radio shows a video (Twitch or YouTube): watching together needs no input. The AFK status shows regardless. Once the video ends, the next sweep moves them. No exception for people sharing or watching camera/screen (not chosen).
- **One time, fixed at 10 minutes (user's decision of 17 September 2026, replacing the first version of the same day):** "Wir sollten die 10 Minuten bis AFK Zustand doch fest schreiben, es macht wegen des Verzeichnis keinen Sinn wenn jeder Server das für sich einstellen kann." The first version had the status after 5 minutes and a move time per server (5/10/15/30/60 minutes, `afkMoveMinutes`, column `afk_move_minutes` from migration 0020). Since friends see one state through the directory and the same person sits on several servers, there is now one time for everything: absent after 10 minutes, and the server moves a member of a voice channel to the AFK channel at that moment. The setting, `AFK_MOVE_MINUTES` and the column are gone (migration 0021 drops the column; 0020 had already run on the dev database and generated SQL is not edited by hand). The only server setting is which channel is the AFK channel.

How it works:
- **The client measures, the servers combine.** `ActivityTracker` (pure, tested) turns idle after `AFK_AFTER_MS`; the store reports every change as `{ type: "activity", idle }` on every chat server connection and on the directory socket. A connection counts as active until it says otherwise (a fresh or reloaded client is somebody using it); after a reconnect only `idle: true` is repeated. A user is AFK once **all** their connections are idle (`Hub` on the chat server, `Hub` in the directory's `friends.ts`), so a second tab or device in use keeps them present; a client from before the feature never reports idle and so keeps its user present.
- **No `PROTOCOL_VERSION` bump and no `DIRECTORY_WS_VERSION` bump.** A server that knows the event sends `settings.afkChannelId` (null = no AFK channel; the field missing = a server from before the feature; a flag like `radioAutoStop`), the directory reports `features.afk`; the client sends `activity` only then (an older server would answer `bad_message`). `Member.afk`, `Friend.afk` and `friends.presence.afk` default to false; older clients strip the unknown fields and `reason` of `voice.moved`.
- **Status:** `Member.afk` travels with the member list (the hub's presence listeners fire on AFK changes too, `broadcastStructure(["members"])`). Shown as an amber crescent on the avatar's presence dot (`Avatar` prop `afk`, label "Abwesend"/"Away"; brand: amber = away, the shape carries the state as well as the color) in the member list and the friends list, and as a moon next to voice members in the sidebar.
- **Move:** `AfkMover` (`voice/afk.ts`, pure, tested) is asked on every presence change (so right when somebody turns absent) and every 5 s (a video that held its channel's members back ends without an event): AFK users sitting in a voice channel that is not the AFK channel and shows no video get `voice.moved` with `reason: "afk"` (`by` = server name), at most once per absence. When the connection a user was active on closes and only idle ones remain, the hub waits `AFK_AFTER_MS` before it calls them absent (they were active a moment ago; tested with fake timers). The client joins the AFK channel itself, like after a moderator's move, remembers where it came from and leaves the view alone (`joinVoice` option `auto`).
- **AFK channel is enforced by LiveKit:** `POST /api/rtc-token` for the AFK channel grants `canPublish: false, canSubscribe: false`; participants still see who is there. The client joins with `JoinOptions.afk`: no microphone request at all, shown muted and deafened (attribute `deafened` for the others), mute/deafen/camera/screen refused and the buttons disabled, no radio control. When the admin changes which channel it is, the server silences the members already inside through `RoomServiceClient.updateParticipant` (`LivekitAdmin.silence`) and gives the old channel's members their grants back (`setCanStream`); current clients additionally rejoin with a fresh token (App.tsx compares the channel's role with `voice.afkRoom`). The AFK channel has no radio: `PUT /api/channels/:id/radio` answers 409 `afk_channel`, and a running radio is turned off when the channel becomes the AFK channel. Anyone may join the AFK channel by hand.
- **Setting:** `server_settings.afk_channel_id` (FK to channels, `on delete set null`; deleting the channel broadcasts the settings too; migration 0020, and 0021 drops the first version's `afk_move_minutes`), `PATCH /api/settings` with `MANAGE_SERVER` (400 `unknown_channel` for anything but a voice channel). Admin area > Kategorien/Kanäle, section "AFK-Kanal" (only with `MANAGE_SERVER`; it is about a channel, so it lives there).

Limits: a browser only sees input in its own windows unless the user allows the Idle Detection API; a background tab checks its timer about once a minute (browser throttling), so the status can come up to a minute late there. A speech gate held open by background noise keeps its user present. The directory operated at https://directory.squorli.com shows AFK to friends only once it runs this version (`features.afk`).

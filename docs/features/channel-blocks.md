**Channel blocks and a clearer member menu (24 September 2026, user's wishes):** "Im Contextmenü in der Benutzerliste auf der rechten Seite sollen die Lautstärkeeinstellungen nicht sein, 'Kicken' und 'Bannen' sollen klar erkennbar sein, dass es sich um Serveraktionen handelt. Aus dem Sprachkanal entfernen soll ein eigener Punkt sein und nicht in 'verschieben nach...' man soll es direkt klicken können, es soll aber auch ein Untermenü aufgehen in dem man eine zeitliche Sperre für den Kanal einstellen kann (5 Minuten, 15 Minuten, 30 Minuten, 60 Minuten, permanent). Es muss für Mods/Admins eine Möglichkeit geben zeitliche Sperren wieder aufzuheben."

- *The member menu (`MemberList.tsx`):* no volume slider any more (it stays in the menus of a voice member in the sidebar and of a stage tile, where one listens to that person). "Verschieben nach …" holds only the other voice channels. "Aus dem Sprachkanal entfernen" is an entry of its own: a click removes (the move to `null` as before); hovering it, ArrowRight or a tap on its arrow opens "Entfernen und sperren für …" with 5, 15, 30, 60 minutes and "Dauerhaft" (`ContextSubmenu` with `onActivate`: the arrow is `.submenu-arrow`). Under the voice part the member's running blocks in channels where I may lift them ("Kanalsperren": "Sperre für X aufheben", the time left, "per Abstimmung" for a vote kick's); a click lifts and the menu stays open. Kick and ban sit last under a section title "Server" with a server icon and are named "Vom Server kicken" / "Vom Server bannen" (their confirmations too).
- *The channel dialog:* a voice channel gets the category "Sperren" for whoever may move members there: every blocked member with the time left and who set it (or "per Abstimmung"), each with "Aufheben".
- *Server:* `PUT /api/channels/:id/blocks { userId, minutes: 5|15|30|60|null }` sets or replaces a block (null = permanent); when the member sits in the channel they get `voice.moved { channelId: null, reason: "blocked", until }` and are removed (presence, LiveKit, a sticky hold released), and a move grant into that channel is dropped. `DELETE /api/channels/:id/blocks/:userId` lifts one (404 when none runs). `GET /api/channel-blocks` lists the running blocks of every channel in which the asker sees the channel and holds `MOVE_MEMBERS`. The token route answers `403 channel_blocked` with `until` (null = permanent), `voice.join` answers `forbidden` with the message `channel_blocked`; a vote kick's block keeps its own code `votekicked`. A moderator's move into the channel still wins over a block, as it did for the vote kick.
- *Persistence:* the table `channel_blocks` (primary key channel + user, `until` null = permanent, `source` moderator/votekick, `blocked_by`) is the truth, so a permanent block survives a restart; `ChannelBlocks` keeps a copy in memory so the token route asks without a query, drops a block that ran out when it is next asked about, and removes rows that ran out while the server was down at start. Single node, like the voice presence.
- *The vote kick's 15-minute block is a channel block now* (`source: "votekick"`), so a moderator sees and lifts it like any other; before, it lived in memory in `VoteKicks` and a restart forgot it.
- *Decisions made by Claude, not asked:* setting and lifting need `MOVE_MEMBERS` resolved in the channel (the right that removes somebody from it; owners and administrators have it); setting one also needs a rank above the member, lifting one does not; blocking oneself is refused; a kick or ban clears the member's blocks (like their channel overwrites); a block may be set on a member who is not in the channel (the route allows it, the client only offers it on a member sitting there); a new block replaces a running one; the lift entries are shown only to whoever holds `MOVE_MEMBERS` server-wide (the menu's other voice entries follow the same flag, while the channel dialog asks per channel); the notice for the removed member names the moderator and the minutes or "dauerhaft". A client from before this change drops the `voice.moved` with the new reason; LiveKit removes it anyway, so it hangs up with the generic "connection lost" handling.
- *Protocol:* no `PROTOCOL_VERSION` bump: new REST routes and codes, one new optional reason and field on `voice.moved`.
- *Checked:* root typecheck, tests (protocol 94, server 105 with `voice/channelBlocks.test.ts` 4 (timed block and its end, permanent across a restart, rows that ran out while down, lift/replace/clear), web 390, desktop 74) and root build. Smoke test against `chat_smoke` on :3001: 190 checks green, 8 of them the new section "Channel blocks" (only with `MOVE_MEMBERS`, only the offered durations, never oneself; 5 minutes with the removal, reason and `until`; the presence drops the member; no token and no `voice.join` there while another channel stays open; the list for the owner with `blockedBy` and empty for a guest; permanent replaces the timed one; a guest may not lift, the owner may, a second lift is 404, the channel is open again; a kick clears the blocks) and one in "Vote kick" (the vote's block in the moderator's list as `votekick`, lifting it opens the channel). Migration 0031 applied to the dev database after a second restart of the user's dev server.
- *Removed members got an error instead of a notice (24 September 2026, user's report):* "Fehler – Getrennt durch den Server (PARTICIPANT_REMOVED). Sollte ein sinnvoller Text sein, der bei einer zeitlichen Sperre auch die Information über die Dauer enthält. Außerdem ist es kein Fehler sondern ein Hinweis." Cause: the server removed the LiveKit participant right after sending `voice.moved`; when LiveKit's disconnect reached the client first, `explainDisconnect` reported it as an unexpected error, and the `voice.moved` that followed was dropped because the voice connection already counted as gone. Fixed three ways: the server removes the participant only after `REMOVE_GRACE_MS` (2 s, `voice/removeLater.ts`, tested; skipped when the member sits in that channel again), so a client hangs up by itself on the event with the notice "{by} hat dich aus dem Sprachkanal entfernt. Du kannst ihn N Minuten lang nicht wieder betreten." (or "dauerhaft"); `PARTICIPANT_REMOVED` is no error any more in the voice client, and when no notice arrives within 1.5 s it says "Du wurdest aus dem Sprachkanal entfernt." as a notice; App.tsx still takes a removal (`voice.moved` with `channelId` null) from the server of the last voice connection after the connection is gone (`lastVoiceHostRef`). The vote kick's removal goes through the same grace. Checked: typecheck, tests (server 107 with `removeLater.test.ts` 2), build, smoke 190 green again. Not checked: the notice with a real voice connection in a browser.
- *The same voice entries in the channel list's menu; "Kamera/Bildschirm beenden" greyed when nothing runs (24 September 2026, user's wishes):* "Sprachkanal relevante Informationen aus dem Benutzer Context-Menü sollen auch in dem Context-Menü des Benutzers in der Kanalliste sein. 'Kamera/Bildschirm beenden' soll ausgegraut sein wenn der Benutzer weder Kamera an hat noch seinen Bildschirm teilt." Built: `VoiceMemberActions.tsx` holds the voice part of a member's menu (the channel they sit in, "Verschieben nach …", "Aus dem Sprachkanal entfernen" with the block submenu, "Kamera/Bildschirm beenden", streaming block, the member's channel blocks to lift, the vote kick) and is used by `MemberList.tsx` and by the voice member menu in `Sidebar.tsx` (there under the volume slider, which stays). "Kamera/Bildschirm beenden" is disabled with the tooltip "Weder Kamera noch Bildschirmfreigabe sind an." while the member has neither on: from LiveKit when the sidebar's viewer sits in the same room, otherwise what the member's client reported (`VoiceMember.cameraOn`/`screenOn`). Checked: typecheck, web tests 390, build. Not checked: both menus in a browser.

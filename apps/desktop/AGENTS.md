# apps/desktop – Desktop app (`@squorli/desktop`)

Part of the project description. The entry point is the root [AGENTS.md](../../AGENTS.md) (commands, definition of done, cross-cutting conventions, the map of all documentation in its section 0). Whoever adds, removes or repurposes a file here, or changes a convention or pitfall, updates this file in the same step. Decisions, phases and what was checked: `docs/features/desktop.md`.

**The app has no renderer code.** It is an Electron shell around the web client: the window shows the build of `apps/web` (`apps/web/dist`) from `app://squorli`. Everything a user sees is changed in `apps/web`; what differs between browser and app goes through `apps/web/src/platform/` (`Platform`, the bridge contract `bridge.ts`). After a client change run `pnpm build` (root) before `pnpm --filter @squorli/desktop start`; `pnpm dev:desktop` shows the Vite server instead.

## Structure

```
apps/desktop/
  package.json         version = the app's version (release tag `desktop-v<version>`); every dependency is a devDependency, because the bundles contain everything except `electron`
  tsup.config.ts       two CommonJS bundles: out/main.cjs (main process), out/preload.cjs; `noExternal` must leave `electron` out (it wins over `external`)
  electron-builder.yml packaging: NSIS installer per user (Windows x64), AppImage + deb (Linux), artifact names WITHOUT spaces, the web client's build as `resources/renderer` (no source maps), LICENSE/NOTICE/THIRD-PARTY-NOTICES as resources, protocol `squorli`, generic update feed `https://squorli.com/updates/stable`, fuses (no run-as-node, no NODE_OPTIONS, no --inspect, cookie encryption, app only from the asar)
  build/icon.png       the app icon, GENERATED by `node tools/desktop-icon.mjs` from docs/brand/squorli-icon.svg (brand tile #0C1424); electron-builder derives .ico and the Linux sizes
  release/             output of `pnpm --filter @squorli/desktop dist` (ignored by git)
  scripts/run.mjs      starts the unpackaged app with ELECTRON_RUN_AS_NODE removed (VS Code's terminals set it; Electron would run as plain Node)
  src/main/index.ts    entry: arguments (unpackaged only: --dev-url, --directory-url, --no-player-fix), user agent, scheme, single instance, window (sandbox, context isolation, no node integration, backgroundThrottling off so voice survives minimizing), `DesktopInfo` for the preload script, IPC with sender check (`isClientFrame`: the client's own main frame only)
  src/main/appFiles.ts pure, tested: `APP_ORIGIN` (`app://squorli`), path -> file with traversal guard and single-page fallback, content types, the Content-Security-Policy
  src/main/scheme.ts   registers `app` as a privileged scheme (before ready) and serves the client's files (after ready), CSP header on HTML
  src/main/navigation.ts pure, tested: what `window.open` may open (about:blank for video pop-outs, /player-window.html), what goes to the system (http, https, mailto), what a main frame may navigate to
  src/main/security.ts permission handlers (the client: media, display-capture, fullscreen, speaker-selection, idle-detection, clipboard write, window-management; embedded players: fullscreen), window-open and navigation lock, no webviews, `openExternal` behind the allow list, `letPlayersEmbed` (Twitch/YouTube, see pitfalls)
  src/main/deepLinkArgs.ts pure, tested, no Electron import (tests run without Electron's binary): the first valid `squorli://` argument
  src/main/deepLinks.ts link at start, from a second start (single-instance lock) and `open-url`; delivered once the client subscribed; a packaged app registers the scheme
  src/main/appearance.ts pure, tested: which window materials the system offers (Windows 11 22H2+), normalizing a stored/sent appearance; config.ts = `<userData>/desktop-config.json`
  src/main/displayMedia.ts `setDisplayMediaRequestHandler`: lists screens and windows (`desktopCapturer`), asks the client's picker over IPC, answers with the source and, on Windows when chosen, `audio: "loopback"`; no answer within two minutes = refused
  src/main/userAgent.ts pure, tested: `… Squorli-Desktop/<version> Chrome/<v> Electron/<v> Safari/537.36`
  src/preload/index.ts the bridge `window.squorliDesktop` (contextBridge): plain data both ways, the page never sees ipcRenderer or an event
```

## Packaging and releases

- Local installer: `pnpm build` (root), then `pnpm --filter @squorli/desktop dist` -> `apps/desktop/release/` (`Squorli-Setup-<version>.exe`, its `.blockmap`, `latest.yml`, `win-unpacked/`). Unsigned (`CSC_IDENTITY_AUTO_DISCOVERY=false` avoids a certificate search).
- **Release:** set `version` in `apps/desktop/package.json`, commit, tag `desktop-v<version>` (the workflow refuses a tag that does not match). The GitLab push mirror carries the tag to GitHub, where `.github/workflows/desktop-release.yml` builds on windows-latest and ubuntu-latest and collects exe, blockmap, AppImage, deb, `latest.yml` and `latest-linux.yml` in a **draft** release. A person tests and publishes the draft; the update feed follows from squorli-website (P4). Tags `v*` are the server image's; both pipelines' image jobs ignore `desktop-v*`. GitLab builds no installers.
- **Open:** the deb target needs `linux.maintainer` with an e-mail address that becomes public (electron-builder.yml); the user has to name one. Until then the Linux job of the release workflow fails at the deb step.
- Third-party notices: the bundles contain only what the web client already lists (zod, from the protocol package) and Electron ships its own `LICENSE.electron.txt` and `LICENSES.chromium.html`. A new bundled main-process dependency (electron-updater in P4) needs an entry in `THIRD-PARTY-NOTICES.md` (`tools/licenses.mjs` reads `apps/web` only).

## Conventions

- **Security baseline, do not weaken:** `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `webSecurity: true`; every `ipcMain` handler checks `isClientFrame(event)`; nothing reaches `shell.openExternal` except through `openExternal()` (http, https, mailto); child windows get no preload; a packaged app ignores every development argument. New IPC channels are added to `IPC` in `apps/web/src/platform/bridge.ts`, to the preload bridge and to `Platform`, in that order.
- **`app://squorli` is final once a public version exists.** The client keeps the user's key (`chat.identity.v1`) and sessions in that origin's localStorage; renaming scheme or host loses them for every user.
- **Pure logic goes into its own module with tests** (`appFiles.ts`, `navigation.ts`, `userAgent.ts`); the Electron-bound files stay thin. `bridge.ts` and `deepLink.ts` of the web package must stay DOM-free: the main process bundles and runs them. (The compiler does not enforce it: the protocol package they pull in needs the DOM library's `CryptoKey` type, so this package is typechecked with the default libraries like the server.)
- **Tests must not import `electron`:** the package's entry throws when its binary is missing, which is the case in CI (`ELECTRON_SKIP_BINARY_DOWNLOAD=1`). Keep what is tested in modules without that import.
- The fixed directory is `https://directory.squorli.com`; `--directory-url` exists for development only.

## Known pitfalls

- **`ELECTRON_RUN_AS_NODE=1`** (set by VS Code in its terminals, also for agents run from it): Electron starts as plain Node, `require("electron").app` is undefined and the app dies with "Cannot read properties of undefined (reading 'isPackaged')". Start through `scripts/run.mjs` (the `dev`/`start` scripts do) or remove the variable.
- **Electron's binary after `pnpm install`:** pnpm 10 only runs install scripts of packages listed in `onlyBuiltDependencies` (pnpm-workspace.yaml lists `electron`). If `node_modules/electron/dist` is missing anyway (it was, right after adding the package on 18 September 2026), run `node node_modules/electron/install.js` in `apps/desktop`. CI test jobs and the Docker build set `ELECTRON_SKIP_BINARY_DOWNLOAD=1`: they never start the app.
- **Twitch and YouTube under `app://`:** without help Twitch refuses to be framed (its `frame-ancestors` names `https://<parent>`, and the parent is the host name `squorli`) and YouTube shows "Fehler 153" (no http(s) referrer). `letPlayersEmbed()` drops `frame-ancestors` for `https://player.twitch.tv/*` and sets `Referer: https://squorli.com/` for `https://www.youtube-nocookie.com/embed/*`, for exactly these hosts. Checked with and without it on 18 September 2026 (`--no-player-fix`).
- **Driving the app from a script:** start `electron.exe <apps/desktop> --remote-debugging-port=<port> --user-data-dir=<dir>` (variable above removed) and attach over the DevTools protocol. `--use-fake-device-for-media-stream` gives a microphone; **never add `--use-fake-ui-for-media-stream`**: it answers `getDisplayMedia` itself and the picker never appears. `Runtime.evaluate` ignores the page's CSP unless `allowUnsafeEvalBlockedByCSP: false` is passed.
- **Windows Firewall** asks once for "Electron" when the first voice connection opens its UDP port (unpackaged app; a packaged one asks for "Squorli").
- Cancelling the picker reaches the page as `AbortError` ("Invalid capture constraints"), which the voice client already treats as a cancel.

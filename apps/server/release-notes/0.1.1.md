A small release for running a server: a restore command for the installer's backups, and LiveKit on a fixed version. Nothing changes for your members.

## Before you update

- **No database change, no new variable, no new desktop app.** Pulling the new image is enough for the version itself.
- **The two changes below live in the deploy files, not in the image**, so `squorli update` alone does not bring them. To get them on an installation made with the install script, download the script again and run it (`curl -fsSL https://raw.githubusercontent.com/danielklessa/squorli-server/main/deploy/install.sh -o install.sh`, then `sudo bash install.sh`); it keeps your settings, secrets and data. With your own Compose or Portainer setup, change the LiveKit image yourself (see below).

## New

- **`squorli restore <folder>`** plays back a backup made with `squorli backup`: it replaces the database and all uploaded files of the installation and starts it again. It asks you to type `yes` first (`--yes` skips the question). Your `.env` is left as it is. Restore with at least the server version that wrote the backup.

## Improved

- **LiveKit on a fixed version.** The Compose files now name `livekit/livekit-server:v1.13.7` instead of `latest`, so a new LiveKit release no longer reaches your server before it was tested with Squorli. Installations that keep their old `compose.yml` stay on `latest`; with your own setup, set the image to `livekit/livekit-server:v1.13.7`.

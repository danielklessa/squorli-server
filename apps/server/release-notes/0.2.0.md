A security release. A review of the sign-in path found several ways in that are closed now; please update soon. Your members notice little: a few links and files behave differently, see below.

## Before you update

- **Back up first** (`squorli backup`): the update adds one database change (a key for signed attachment links). It runs at the start and cannot be undone.
- **`PUBLIC_DOMAIN` must be the address your members reach the server at.** Clients of other servers and the desktop app now refuse to sign in to a server whose `PUBLIC_DOMAIN` names another address than the one they connect to. That was always required for the server's own web client; check it if members come in through another name.
- **New optional variable `RATE_LIMIT_FACTOR`** (default `1`). The server now limits requests per address and per session. If your reverse proxy runs on another host, its address must be in `TRUSTED_PROXIES`, otherwise every member shares the proxy's address and the limits hit all of them at once. `2` doubles every limit, `0` switches them off (meant for load tests).
- **`DIRECTORY_PROOF_URL`**, if you set it at all, must end in `/api/health` on the server's own host; the directory accepts no other address any more.
- **A new desktop app follows right after this server.** Older apps keep working; until members update, pictures in a channel they keep open for more than a week can stop loading, and the camera and screen permission of a voice channel is not yet applied by their app.

## New

- **Rate limits** on sign-in, messages, uploads, invites, the status API and the connection itself. A member who sends too much gets a short "please wait" instead of the request going through.
- **Server account passwords are bound to your server.** New server accounts and every password change use a derivation that includes the server's address, so a password reused elsewhere is worth nothing to another server. Existing accounts switch at their next sign-in with the password.

## Improved

- **Attachment links expire.** The address of an uploaded file now works for about a week; a link passed around outside the server stops working after that, and a member who loses access to a channel gets no fresh links for its files. The client loads new links by itself.
- **Only harmless file types open in the browser:** pictures (PNG, JPEG, GIF, WebP, AVIF), video, audio, plain text and PDF. Everything else, SVG and HTML included, is downloaded instead of shown.
- **The camera and screen permission of a voice channel now counts.** A channel that denies watching to a role or member really keeps camera and screen from them (with the new desktop app, and in the browser at once).
- **Members from before server accounts** who create one now get a fresh key for this server; their messages and roles move with them.

## Fixed

- **A malicious server could sign a member in to another server.** A server a member added could claim to be another one and pass the member's sign-in on. Clients now sign only for the address they actually connect to.
- **A server could add itself to members' server lists** at the directory, and clients connected to it on their own. The directory now lists a server only after a member really signed in there, and clients connect by themselves only to servers they know.
- **A web radio playlist could be used to reach addresses inside the server's network** by switching its name's address between the check and the download.
